# Browser Agent — Implementation Plan (v2)

## Repositories

| Repo | Role | Status |
|---|---|---|
| `python-input-control` | Native messaging host — executes OS-level mouse/keyboard/scroll | ✅ Complete, use as-is |
| `browser-agent-core` | Reusable extension framework (NEW separate git repo) | 🔲 Build |
| `browser-agent-ext` | Reference extension — popup UI + wires the framework | 🔲 Build |

## Architecture

```
browser-agent-ext/               browser-agent-core/ (git submodule)
├── manifest.json                ├── background/
├── lib/                         │   ├── agent.js          ← AgentCore class
│   └── browser-agent-core/ ◄───┤   ├── browser-bridge.js ← chrome.tabs.* wrapper
├── background/sw.js             │   ├── executor.js       ← action execution
│   imports AgentCore ───────────┤   ├── input-control.js  ← python-input-control bridge
├── popup/popup.html+js          │   └── llm/              ← provider implementations
└── options/options.html+js      └── content/
                                     └── extractor.js      ← standalone IIFE content script
                                                             (listed directly in manifest)
```

**Data flow for one agent iteration:**

```
Popup sends {type:'start_task', task:'...'}
        │
        ▼
Service Worker (sw.js)
  1. Reads config from chrome.storage.local (API key, provider, model)
  2. Creates AgentCore with chosen LLMProvider
  3. Calls agent.run(task)
        │
        ├─► BrowserBridge.navigate(url)            → chrome.tabs.update + wait for load
        │
        ├─► BrowserBridge.getPageState(tabId)      → chrome.tabs.sendMessage → extractor.js
        │       returns: {url, title, elements[], context, viewport}
        │
        ├─► BrowserBridge.takeScreenshot()         → chrome.tabs.captureVisibleTab
        │       returns: base64 PNG string
        │
        ├─► LLMProvider.complete({system, messages, screenshot})
        │       fetch() to OpenAI/Anthropic/Ollama/etc.
        │       returns: raw text with JSON
        │
        ├─► if done → report status, stop
        │
        ├─► ActionExecutor.execute(actions, pageState)
        │       auto-prepend mouse_move before click
        │       auto-scroll out-of-viewport elements
        │       inject BrowserContext into each action
        │       for each action:
        │           InputControlBridge.execute(command, params, context)
        │               → chrome.runtime.connectNative('com.workshop.python_input_control')
        │               → send {id, command, params, context} native message
        │               → await response {id, status, error}
        │
        └─► repeat from getPageState
```

### Task 1.3 — `background/agent.js` — `AgentCore`

The main orchestration class. Service workers import and instantiate this.

**Constructor:**
```javascript
new AgentCore({
  llm,                       // LLMProvider instance, required
  onStatus,                  // function(StatusUpdate) => void, required
  maxIterations,             // default 20
  useVision,                 // default true — send screenshots to LLM
  actionSettleMs,            // default 1500 — wait after executing actions
  navigationTimeoutMs,       // default 30000
})
```

**Public methods:**
- `async run(task)` — starts the agent loop, returns final message string
- `stop()` — sets internal flag to abort loop gracefully after current iteration
- `systemPrompt()` — returns the system prompt string; **override in subclass** to specialise behaviour
- `buildUserMessage(task, pageState, iteration, history)` — builds the user message for this iteration; **override in subclass** to add domain-specific context

**Status model** (passed to `onStatus` on every state change):
```javascript
{
  state: 'idle' | 'running' | 'thinking' | 'acting' | 'done' | 'error' | 'stopped',
  task: string | null,
  iteration: number,
  maxIterations: number,
  url: string | null,
  title: string | null,
  message: string | null,     // final message when done, error description when error
  actionsCount: number | null, // number of actions in current iteration
  timestamp: number,           // Date.now()
}
```

**Every status update is also written to `chrome.storage.local` under key `'agentStatus'`** so popup can read it on open.

**Agent loop logic:**
```
run(task):
  report status: running, iteration 0
  extract URL from task (regex for http/https)
  if URL found: await bridge.navigate(url)

  for i in 0..maxIterations-1:
    if stopped: report stopped, return
    report status: thinking, iteration i, current url

    pageState = await bridge.getPageState(activeTabId)
    if useVision: screenshot = await bridge.takeScreenshot()

    rawResponse = await llm.complete({
      system: this.systemPrompt(),
      messages: buildHistory(task, pageState, screenshot, i, messageHistory)
    })
    append rawResponse to messageHistory

    parsed = parseJSONResponse(rawResponse)
    if parse fails: retry once with a follow-up message asking for valid JSON
    if parse fails again: report error, return

    if parsed.done:
      report status: done, message: parsed.message
      return parsed.message

    report status: acting, actionsCount: parsed.actions.length
    await executor.execute(parsed.actions, pageState)
    await sleep(actionSettleMs)

  report status: error, message: 'Max iterations reached'
  return null
```

**`buildHistory` function** (internal):
- First iteration: `[{role:'user', content: buildUserMessage(task, pageState, 0, [])}]`
- Subsequent iterations: append assistant response + new user message to rolling history
- Cap at last 10 user+assistant pairs to avoid context blowup

**Default system prompt** (stored as a constant, returned by `systemPrompt()`):
```
You are a browser automation agent. You control a real web browser.
You are given:
- A task to complete
- A list of interactive elements on the current page with their IDs, labels, types, and viewport-relative coordinates
- The current URL and page title
- Optionally a screenshot of the visible viewport

Respond ONLY with a JSON object. No prose, no markdown, no code fences. Two possible shapes:

1. More actions needed:
{"done":false,"reasoning":"brief explanation","actions":[...]}

2. Task complete:
{"done":true,"message":"description of what was accomplished"}

Action shapes (same as python-input-control command protocol):
- {"command":"mouse_click","params":{"x":320,"y":150}}
- {"command":"mouse_click","params":{"x":320,"y":150,"button":"right"}}
- {"command":"mouse_click","params":{"x":320,"y":150,"count":2}}
- {"command":"type","params":{"text":"hello@example.com","wpm":80}}
- {"command":"press_key","params":{"key":"Tab"}}
- {"command":"press_key","params":{"key":"Enter"}}
- {"command":"press_shortcut","params":{"keys":["control","a"]}}
- {"command":"scroll","params":{"x":640,"y":400,"delta_x":0,"delta_y":300,"duration_ms":400}}
- {"command":"mouse_move","params":{"x":320,"y":150,"duration_ms":400}}
- {"command":"pause","params":{"duration_ms":300}}
- {"command":"navigate","params":{"url":"https://example.com"}}

RULES:
1. Use coordinates from the elements list. Center of element = rect.x + rect.width/2, rect.y + rect.height/2.
2. NEVER click an element where inViewport is false. First emit a scroll command to bring it into view.
3. Always click a field before typing into it.
4. Include a pause (200-400ms) between groups of related actions.
5. If a CAPTCHA or login wall blocks progress and you cannot proceed, set done:true with a clear message.
6. If asked to navigate to a URL, use the navigate command.
7. Keep reasoning brief and factual.
```

**`buildUserMessage` default format:**
```
Task: {task}

Current page: {url} — "{title}"

Interactive elements ({count} total, viewport {vw}×{vh}, scroll {sx},{sy}):
[el_0]  INPUT[email]   "Email address"         placeholder="you@example.com"  at (320,220) 280×40  ✓ viewport
[el_1]  INPUT[password] "Password"             placeholder="Password"          at (320,280) 280×40  ✓ viewport
[el_2]  BUTTON          "Log In"                                                at (320,340) 280×44  ✓ viewport
[el_3]  A               "Forgot password?"                                      at (320,400) 120×20  ✓ viewport
[el_4]  BUTTON          "Create new account"                                    at (320,520) 200×40  ✗ not in viewport

{if iteration > 0: "\nPrevious actions have been performed. Evaluate current state and continue or declare done."}
```

**`parseJSONResponse(text)` utility:**
- Try `JSON.parse(text)` directly
- If fails, look for first `{` and last `}`, try parsing that substring
- Validate result has `done` boolean field
- Return parsed object or throw `ParseError`

### Task 1.4 — `background/browser-bridge.js` — `BrowserBridge`

Wraps all `chrome.*` API calls. Can be mocked entirely in tests.

**Methods:**

`async getActiveTabId()`
- `chrome.tabs.query({ active: true, currentWindow: true })`
- Returns tab id of the current active tab
- Throws `BridgeError` if no active tab found

`async getPageState(tabId)`
- `chrome.tabs.sendMessage(tabId, { type: 'get_page_state' })`
- Returns the `PageState` object from the content script
- If message fails (content script not injected), inject it first via `chrome.scripting.executeScript` then retry once
- Timeout: 10 seconds — throws `BridgeError` if no response

`async takeScreenshot()`
- `chrome.tabs.captureVisibleTab(null, { format: 'png' })`
- Returns base64 data URL string
- If fails (e.g. chrome:// pages), returns `null` silently rather than throwing

`async navigate(url, timeoutMs)`
- `chrome.tabs.update({ url })`
- Waits for `chrome.webNavigation.onCompleted` on the same tab
- Also waits for an additional 500ms after load (DOM settle)
- Throws `NavigationTimeoutError` if timeoutMs exceeded
- `timeoutMs` default 30000

`async waitForPageSettle(tabId, ms)`
- Sends `{ type: 'wait_for_settle' }` to content script
- Content script watches for `MutationObserver` to be quiet for 500ms then responds
- Used after executing actions before taking next page state
- Has a hard timeout fallback of `ms` (default 3000)

`sendStatus(status)`
- `chrome.storage.local.set({ agentStatus: status })`
- Then attempt `chrome.runtime.sendMessage({ type: 'agent_status', status })` — catch and ignore errors (popup might be closed)

### Task 1.5 — `background/input-control.js` — `InputControlBridge`

Wraps the native messaging connection to `python-input-control`.

**Native host name:** `com.workshop.python_input_control`

**Design:** Maintains a single persistent `chrome.runtime.Port`. Sends one command at a time, awaits its response (matched by `id` field). Queues concurrent calls.

**Methods:**

`async connect()`
- `this._port = chrome.runtime.connectNative('com.workshop.python_input_control')`
- Sets up `onMessage`, `onDisconnect` listeners
- On `onDisconnect`: set `this._port = null`, reject all pending promises
- Returns when connected (synchronous in Chrome, no async handshake needed)

`async execute(command, params, context)`
- If not connected, calls `connect()` first
- Generates `id = crypto.randomUUID()`
- Creates `Promise` stored in `this._pending` map keyed by `id`
- Posts message: `{ id, command, params, context }` via `this._port.postMessage()`
- `onMessage` listener resolves/rejects matching pending promise when response arrives
- Timeout: 30 seconds — rejects with `InputControlTimeoutError`
- If response has `status: 'error'`, rejects with `InputControlError(response.error)`

`disconnect()`
- Calls `this._port.disconnect()` if connected
- Clears all pending promises

**Context injection note:** `execute()` requires the full `context` object (BrowserContext). The caller (ActionExecutor) is responsible for passing it from the current `PageState`.

### Task 1.6 — `background/executor.js` — `ActionExecutor`

Receives a list of actions from the LLM and executes them with human-like behaviour.

**Constructor:** `new ActionExecutor({ bridge, inputControl })`

**`async execute(actions, pageState)`:**

For each action in order:
1. If `command === 'navigate'`: call `bridge.navigate(params.url)`, continue to next action
2. If `command` is a coordinate command (`mouse_click`, `mouse_move`, `scroll`):
   - Check if params.x, params.y are for an element that is `inViewport: false`
   - If out of viewport: auto-prepend a `scroll` command to bring centre of element to viewport centre:
     `{ command: 'scroll', params: { x: viewportWidth/2, y: viewportHeight/2, delta_x: 0, delta_y: rect.y - viewportHeight/2 + rect.height/2, duration_ms: 400 } }`
   - Wait 300ms after scroll for DOM to settle before continuing
3. If `command === 'mouse_click'` and the immediately preceding action was NOT a `mouse_move` to the same coordinates:
   - Auto-prepend `mouse_move` with same x, y and a randomised `duration_ms` between 300 and 700ms
4. Execute the action: `await inputControl.execute(command, params, pageState.context)`
5. After execution: sleep a random duration between 80ms and 180ms (human micro-pause)
6. After a `type` command: additional 100–250ms pause
7. After a `navigate` command: call `bridge.waitForPageSettle(tabId)`

**`_randomMs(min, max)`** — internal: `Math.floor(Math.random() * (max - min + 1)) + min`

**`_findElementByCoords(x, y, elements)`** — internal: finds the element in the page state elements list whose centre is closest to (x, y). Used to check `inViewport` status.

### Task 1.8 — `background/llm/utils.js`

`parseJSONFromText(text)`
- Attempts `JSON.parse(text.trim())`
- If fails, strips leading/trailing markdown code fences (` ```json ... ``` ` or ` ``` ... ``` `)
- If fails, finds first `{` to last `}` and tries that substring
- Returns parsed object
- Throws `LLMParseError` with original text attached if all attempts fail

`buildImageContent(screenshotDataUrl)`
- Returns the provider-appropriate image object for including a screenshot
- Used internally by providers

`extractJsonBlock(text)`
- Regex: `/```(?:json)?\s*([\s\S]*?)\s*```/` — first match group
- Returns the contents of the first code fence, or null if none found

### Task 1.14 — `content/extractor.js` — DOM Extraction Content Script

**CRITICAL:** This file must be a standalone IIFE with zero imports and zero ES module syntax. It is listed directly in `manifest.json` as a content script. It must run in every page without a build step.

**Structure:**
```javascript
(function () {
  'use strict';

  function getBrowserContext() { ... }
  function getElementLabel(el) { ... }
  function isVisible(el, rect) { ... }
  function isInViewport(rect) { ... }
  function extractInteractiveElements() { ... }
  function getPageState() { ... }

  chrome.runtime.onMessage.addListener(function (message, sender, sendResponse) {
    if (message.type === 'get_page_state') {
      sendResponse(getPageState());
      return true;
    }
    if (message.type === 'wait_for_settle') {
      waitForSettle(500).then(() => sendResponse({ settled: true }));
      return true;
    }
  });

})();
```

**`getBrowserContext()`:**
```javascript
return {
  screenX: window.screenX,
  screenY: window.screenY,
  outerHeight: window.outerHeight,
  innerHeight: window.innerHeight,
  outerWidth: window.outerWidth,
  innerWidth: window.innerWidth,
  devicePixelRatio: window.devicePixelRatio,
  scrollX: window.scrollX,
  scrollY: window.scrollY,
};
```

**`getElementLabel(el)`** — returns the best human-readable label for an element, in priority order:
1. `aria-labelledby` → get `textContent` of each referenced element, join with space
2. `aria-label`
3. `<label for="...">` matching `el.id` → `label.textContent.trim()`
4. Closest ancestor `<label>` → `textContent.trim()`
5. `placeholder`
6. `title`
7. `alt` (for `<img>`, `<input type=image>`)
8. `innerText.trim()` up to 120 chars (for buttons, links)
9. `null`

**`isVisible(el, rect)`:**
- `rect.width > 0 && rect.height > 0`
- `getComputedStyle(el).display !== 'none'`
- `getComputedStyle(el).visibility !== 'hidden'`
- `parseFloat(getComputedStyle(el).opacity) > 0`
- Walk up ancestors: none have `display:none` or `visibility:hidden`
- All checks must pass

**`isInViewport(rect)`:**
- `rect.top < window.innerHeight && rect.bottom > 0 && rect.left < window.innerWidth && rect.right > 0`

**`extractInteractiveElements()`:**

Selector list:
```
a[href], button, input:not([type=hidden]), select, textarea,
[role=button], [role=link], [role=checkbox], [role=radio],
[role=menuitem], [role=tab], [role=option], [role=combobox],
[role=searchbox], [role=textbox], [role=switch], [role=spinbutton],
[contenteditable=true], [tabindex]:not([tabindex="-1"])
```

For each matching element:
- Compute `rect = el.getBoundingClientRect()`
- If `!isVisible(el, rect)` → skip
- Build descriptor:
```javascript
{
  id: 'el_' + index,
  tag: el.tagName,
  type: el.type || null,
  role: el.getAttribute('aria-role') || el.getAttribute('role') || inferRole(el),
  rect: {
    x: Math.round(rect.left),
    y: Math.round(rect.top),
    width: Math.round(rect.width),
    height: Math.round(rect.height),
  },
  inViewport: isInViewport(rect),
  label: getElementLabel(el),
  placeholder: el.placeholder || null,
  value: el.value !== undefined ? el.value : null,
  checked: el.checked !== undefined ? el.checked : null,
  href: el.href || null,
  text: el.innerText ? el.innerText.trim().substring(0, 120) : null,
  enabled: !el.disabled,
}
```

**`inferRole(el)`:**
- `A` → `'link'`
- `BUTTON` → `'button'`
- `INPUT` type `checkbox` → `'checkbox'`, type `radio` → `'radio'`, type `submit`/`button`/`reset` → `'button'`, others → `'textbox'`
- `SELECT` → `'combobox'`
- `TEXTAREA` → `'textbox'`
- `[contenteditable]` → `'textbox'`
- else → `'generic'`

Deduplicate by element reference (a single element may match multiple selectors).

**`waitForSettle(quietMs)`:**
- Creates a `MutationObserver` on `document.body`
- Resets a debounce timer on every mutation
- Resolves when `quietMs` have elapsed without any mutation
- Hard timeout: `quietMs * 4` — resolves anyway

**`getPageState()`:**
```javascript
return {
  url: location.href,
  title: document.title,
  elements: extractInteractiveElements(),
  context: getBrowserContext(),
  viewportWidth: window.innerWidth,
  viewportHeight: window.innerHeight,
  pageWidth: document.documentElement.scrollWidth,
  pageHeight: document.documentElement.scrollHeight,
};
```

### Task 2.2 — `background/sw.js`

This is the extension's entire "backend". Thin — just wires things together.

```javascript
import { AgentCore, BrowserBridge, ActionExecutor, InputControlBridge }
  from '../lib/browser-agent-core/background/index.js';
import { OpenAIProvider, AnthropicProvider, OllamaProvider,
         OpenRouterProvider, NvidiaProvider }
  from '../lib/browser-agent-core/background/index.js';

let currentAgent = null;

function createProvider(config) {
  switch (config.provider) {
    case 'anthropic':   return new AnthropicProvider({ apiKey: config.apiKey, model: config.model });
    case 'ollama':      return new OllamaProvider({ baseUrl: config.baseUrl, model: config.model });
    case 'openrouter':  return new OpenRouterProvider({ apiKey: config.apiKey, model: config.model });
    case 'nvidia':      return new NvidiaProvider({ apiKey: config.apiKey, model: config.model });
    default:            return new OpenAIProvider({ apiKey: config.apiKey, model: config.model });
  }
}

chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === 'start_task') {
    chrome.storage.local.get(
      ['provider','apiKey','model','baseUrl','maxIterations','useVision'],
      (config) => {
        const llm = createProvider(config);
        const bridge = new BrowserBridge();
        const inputControl = new InputControlBridge();
        const executor = new ActionExecutor({ bridge, inputControl });

        currentAgent = new AgentCore({
          llm,
          bridge,
          executor,
          onStatus: (status) => bridge.sendStatus(status),
          maxIterations: config.maxIterations || 20,
          useVision: config.useVision !== false,
        });

        currentAgent.run(message.task).catch((err) => {
          bridge.sendStatus({
            state: 'error', message: err.message, timestamp: Date.now(),
            task: message.task, iteration: 0, maxIterations: 20,
            url: null, title: null, actionsCount: null,
          });
        });
      }
    );
    sendResponse({ started: true });
    return true;
  }

  if (message.type === 'stop_task') {
    if (currentAgent) currentAgent.stop();
    sendResponse({ stopped: true });
    return true;
  }
});
```

**AgentCore** needs to accept `bridge` and `executor` as constructor options (inject them) so the service worker controls instantiation. Update constructor signature in Task 1.3:

## Key Constraints Summary (for all implementing agents)

1. **`content/extractor.js` must be a pure IIFE** — no `import`, no `export`, no ES module syntax. It is injected directly by Chrome into web pages.
2. **Service worker modules use ES module syntax** — `import`/`export` throughout.
3. **No npm runtime dependencies** — only `fetch()` and Chrome extension APIs.
4. **Mouse never teleports** — `ActionExecutor` ALWAYS auto-prepends `mouse_move` before `mouse_click` if not already present.
5. **Viewport check is mandatory** — `ActionExecutor` ALWAYS checks `inViewport` and auto-prepends scroll if needed.
6. **BrowserContext always injected** — `InputControlBridge.execute()` requires the full context object from `PageState.context` — never send a command without it.
7. **Status always written to storage** — `BrowserBridge.sendStatus()` writes to `chrome.storage.local` AND attempts `sendMessage` (best-effort). Popup reads storage on open.
8. **AgentCore is subclassable** — `systemPrompt()` and `buildUserMessage()` are normal methods, not arrow functions or closures, so subclasses can call `super.systemPrompt()` and override.
