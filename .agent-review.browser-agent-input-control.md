## High

### 1) Concurrent `execute()` calls can corrupt tab targeting and mix command state ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/bridge.js:45-60,66-75,83-120,139-152`
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/mouse.js:23-33,40-60`
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/keyboard.js:27-35`
- `browser-agent-ext/lib/browser-agent-input-control/tests/mouse.test.js:108-118`
- Protocol note: `browser-agent-ext/lib/input-control-protocol/PROTOCOL.md:174`

**Issue:**
`CdpInputControlBridge` stores the target tab in one mutable field, `this._activeTabId`, and both backends read it lazily for every low-level CDP send. If two `execute()` calls overlap, the second call can overwrite `_activeTabId` while the first command is still emitting events.

That means a long-running command such as `type`, `mouse_move`, or `scroll` can start on tab A and finish on tab B. The mouse backend also keeps one shared `_lastPoint`, so concurrent mouse commands can distort each other’s motion path as well.

**Why this matters:**
This is the highest-risk race in the package: wrong-tab typing/clicking is a serious correctness and safety problem for an input automation layer.

**Why the architecture is brittle:**
The protocol docs say requests are handled serially, but the public bridge API does not enforce serialization, queueing, or rejection of overlapping commands. Instead, correctness depends on all callers “doing the right thing”.

**What to change:**
Capture immutable per-command execution state before dispatch:
- resolve the tab id once per `execute()`;
- pass that tab id into the dispatcher/backends as part of a command-scoped context;
- make mouse position state tab-scoped or command-scoped, not global mutable bridge state;
- either serialize `execute()` internally or explicitly reject a new command while one is already running.

**Testing gap:**
There is no test for overlapping successful `execute()` calls, no “tab changed during in-flight command” case, and `tests/mouse.test.js:108-118` currently reinforces the late-binding behavior instead of protecting against it.

### 2) `duration_ms === 0` still emits a full mouse path instead of teleporting instantly ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/mouse.js:40-60,63-65`
- `browser-agent-ext/lib/browser-agent-input-control/tests/mouse.test.js:70-79,81-96`
- Protocol requirement: `browser-agent-ext/lib/input-control-protocol/COMMANDS.md:48`

**Issue:**
`CdpMouseBackend.move()` always builds a Bézier path and emits every intermediate `mouseMoved` event. When `durationMs` is `0`, it only removes the sleep; it does **not** collapse to a single final move event.

`click()` inherits the same behavior because it calls `move()` first, so `move_duration_ms: 0` still performs many intermediate hover events before the press.

**Why this matters:**
The protocol explicitly says `mouse_move` with `duration_ms === 0` **must teleport instantly**. The current implementation can trigger unintended hover behavior, tooltip activation, drag/enter/leave handlers, and other page state changes that would not happen with a true instant move.

**Why this is especially risky:**
The tests currently codify the wrong behavior: `tests/mouse.test.js:70-79` uses `durationMs: 0` and expects `moves.length > 1`.

**What to change:**
Short-circuit `move()` when `durationMs === 0` to dispatch exactly one `mouseMoved` event at the target and update cursor state immediately. `click()` should then inherit the correct zero-duration move semantics automatically.

**Testing gap:**
Add assertions that `duration_ms: 0` and `move_duration_ms: 0` emit only one move event before the click.

## Medium

### 3) `type` breaks astral Unicode characters (emoji and other non-BMP code points) ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/keyboard.js:69-81`
- `browser-agent-ext/lib/browser-agent-input-control/src/key-map.js:161-243`

**Issue:**
`typeText()` iterates with `command.text[i]`, which walks UTF-16 code units rather than Unicode code points/graphemes. Characters like `😀` are split into two surrogate halves, and `resolveCharacter()` then treats each half as an independent key.

**Why this matters:**
The command will return success while silently typing corrupted text. For an automation backend, silent corruption is worse than a loud validation failure.

**What to change:**
At minimum, iterate code points (`for...of` on the string) rather than UTF-16 code units. If fidelity matters for complex scripts and emoji sequences, consider grapheme segmentation rather than raw code points.

**Testing gap:**
`tests/keyboard.test.js` only covers ASCII. Add cases for emoji, accented characters, and mixed BMP/non-BMP strings.

### 4) `press_shortcut` does not emit real Shift key transitions for shifted terminal keys ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/keyboard.js:111-157`

**Issue:**
For a shortcut whose final key is a shifted printable character (for example `['ctrl', 'A']` or `['ctrl', '?']`), the implementation only sets the Shift modifier bit on the final key event. It does **not** send actual `Shift` keyDown/keyUp events unless Shift was explicitly listed in the shortcut.

**Why this matters:**
Some apps track modifier state from real key transitions, not only from modifier flags on the terminal event. Those shortcuts can behave differently from real user input.

**What to change:**
Reuse the same shifted-character handling used by `_tapCharacter()`: if the terminal character requires Shift and Shift is not already held, send Shift down before the terminal key and Shift up after it.

**Testing gap:**
Add coverage for uppercase and shifted-symbol shortcut terminals, not just explicit modifier chords like `ctrl+shift+k`.

### 5) Mouse cursor state is global and survives across tabs/commands ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/mouse.js:24-29,40-60`
- `browser-agent-ext/lib/browser-agent-input-control/src/bridge.js:139-152`

**Issue:**
`CdpMouseBackend` stores one `_lastPoint` for the entire backend instance. It is not scoped per tab and is not reset on abort/detach. After a tab switch or overlapping work, the next motion path can start from stale coordinates from a different tab/session.

**Why this matters:**
Even without the tab race above, motion realism and correctness degrade because cursor history is being treated as global singleton state rather than target/session state.

**What to change:**
Track last-known position per tab id, or reset cursor history when the bridge aborts/detaches or the active tab changes.

**Testing gap:**
No tests cover per-tab isolation or state reset after abort/detach.

### 6) Parser is materially looser than the declared frozen protocol ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/dispatcher.js:84-88,100-118,121-155,172-177,261-281`
- Protocol/docs:
  - `browser-agent-ext/lib/input-control-protocol/PROTOCOL.md:39,74`
  - `browser-agent-ext/lib/input-control-protocol/COMMANDS.md:411,507,695`

**Issue:**
Several validations do not match the declared protocol surface:
- missing `context` is accepted (`parseBrowserContext()` returns `{}`);
- `sequence.steps` may be empty even though the command schema says `minItems: 1`;
- `press_key.key` only has to be a string, not a non-empty string;
- `press_shortcut.keys[]` items only have to be strings, not non-empty strings.

This means requests outside the frozen protocol can be accepted here and then fail later with implementation-specific errors (for example `key name must be non-empty`) or succeed when they should have been rejected.

**Why this matters:**
The README positions this package as semantically identical to `python-input-control`. Loose validation increases backend drift and makes behavior less predictable when swapping backends.

**What to change:**
Either:
1. align validation to the protocol exactly, or
2. explicitly document the intentional divergence and add contract tests so it does not drift accidentally.

**Testing gap:**
No tests cover missing `context`, empty `sequence.steps`, or empty key names.

## Low

### 7) `press_key` has no press/release pause and no inter-repeat pause ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/src/backends/keyboard.js:84-109`
- Protocol note: `browser-agent-ext/lib/input-control-protocol/COMMANDS.md:428`

**Issue:**
`pressKey()` emits keyDown/keyUp pairs back-to-back and repeats them back-to-back. The command docs say it **must pause between press and release** and should space repeats with a short pause.

**Why this matters:**
This is lower risk than the tab/mouse issues, but it reduces behavioral fidelity and may make automation look less like genuine user input.

**What to change:**
Introduce a small cancellable delay between keyDown/keyUp and between repeats, ideally sharing timing constants with shortcut handling.

**Testing gap:**
Current keyboard tests only verify event order, not timing behavior.

### 8) Test coverage is strong on transport races but still tightly coupled to sibling internals and fakes ✅
**Files:**
- `browser-agent-ext/lib/browser-agent-input-control/tests/debugger-transport.test.js:3`
- `browser-agent-ext/lib/browser-agent-input-control/tests/cdp-inspector.test.js:2`
- `browser-agent-ext/lib/browser-agent-input-control/tests/**`

**Issue:**
The suite imports `../../pi-browser-agent-bridge/src/cdp-inspector.js` directly and relies heavily on fake transports/debugger APIs. That makes this package harder to validate independently and leaves real integration edges under-covered.

**Why this matters:**
The package has good unit-level race tests, but confidence is still limited for the actual extension/runtime boundary: permission failures, DevTools already attached, active-tab churn, and service worker cleanup.

**What to change:**
- add a thin contract test layer for the inspector interface instead of importing a sibling package’s internal source directly;
- add a few higher-level integration tests around bridge creation and detach/cleanup behavior.

## Recommended priorities
1. Fix command-scoped tab ownership / serialization first.
2. Fix zero-duration mouse semantics next.
3. Fix Unicode typing and shifted shortcut terminal-key handling.
4. Tighten protocol validation and add missing contract tests.
5. Improve state ownership for mouse position and fill remaining integration gaps.
