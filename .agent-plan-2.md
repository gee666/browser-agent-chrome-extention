# Browser Agent — Implementation Plan v2

## What Changes and Why

The v1 implementation has three fundamental problems:

1. **Coordinates in the LLM prompt** — the model sees `(480,442)` and must do arithmetic to click. Coordinates go stale if the page shifts. The model frequently gets them wrong.
2. **Full DOM in every history message** — a 70-element page = ~8 K tokens per message. 6 history pairs = 48 K tokens just for repeated page dumps.
3. **Multiple actions per step** — the model returns an array of low-level commands (`mouse_move`, `mouse_click`, `type`). This is the OS job, not the LLM's job. The LLM should say "click the login button"; the harness figures out scroll → move → click.

The v2 design is adopted from page-agent (Alibaba) + italian_consulate_ext coordinate pipeline:

- **LLM sees indices**, never coordinates: `[5]<button>Log In</button>`
- **LLM emits one semantic action**: `{ "click": { "index": 5 } }`
- **Harness auto-expands** that to: scroll if needed → mouse_move → mouse_click — all via python-input-control, no DOM fallbacks
- **History is summaries**, not full DOM snapshots: one line of reflection per past step

## Part 1 — New `content/extractor.js`

Rewrite as a standalone IIFE (no imports/exports), taking inspiration from page-agent's `dom_tree/index.js`.

### 1.1 Element detection strategy

Priority order for "is this element interactive?":

1. **Explicit blacklist**: elements with `data-page-agent-ignore="true"` or `aria-hidden="true"` → skip
2. **Tag blacklist**: `script, style, link, meta, noscript, template, svg, head` → skip children
3. **CSS cursor check**: `getComputedStyle(el).cursor` is in the interactive cursor set (`pointer, text, crosshair, grab, grabbing, cell, copy, move, e-resize, ...`) → interactive
4. **Tag name**: `a[href], button, input:not([type=hidden]), select, textarea, details, summary, label` → interactive
5. **ARIA role**: `button, link, checkbox, radio, menuitem, tab, switch, combobox, textbox, option, searchbox, slider, spinbutton` → interactive
6. **contenteditable="true"** → interactive
7. Else → not interactive, but still walk children

### 1.2 Visibility check

```javascript
function isVisible(el) {
  if (!el || !el.isConnected) return false;
  if (el.disabled) return false;
  const style = window.getComputedStyle(el);
  if (style.display === 'none' || style.visibility === 'hidden' || style.pointerEvents === 'none') return false;
  const rect = el.getBoundingClientRect();
  return rect.width > 0 && rect.height > 0;
}
```

### 1.3 Scrollable element detection

```javascript
function getScrollInfo(el) {
  const style = window.getComputedStyle(el);
  const overflowY = style.overflowY;
  const overflowX = style.overflowX;
  const scrollableY = (overflowY === 'auto' || overflowY === 'scroll') && el.scrollHeight > el.clientHeight + 4;
  const scrollableX = (overflowX === 'auto' || overflowX === 'scroll') && el.scrollWidth  > el.clientWidth  + 4;
  if (!scrollableY && !scrollableX) return null;
  return {
    top:    el.scrollTop,
    bottom: el.scrollHeight - el.clientHeight - el.scrollTop,
    left:   el.scrollLeft,
    right:  el.scrollWidth  - el.clientWidth  - el.scrollLeft,
  };
}
```

Elements with scroll info get an annotation appended to their text:
`data-scrollable="top=0, bottom=340, left=0, right=0"`

### 1.4 New-element tracking

A `WeakSet<Element>` tracks every element that appeared in the previous extraction.
On each `get_page_state` call, elements NOT in the set are marked `isNew: true` → rendered as `*[index]`.
After extraction, the WeakSet is updated to the current set.

### 1.5 DOM tree walk and index assignment

```javascript
let indexCounter = 0;
const elements = [];  // ordered by DOM order (DFS)

function walk(node, depth) {
  if (node.nodeType === Node.TEXT_NODE) {
    const text = node.textContent.trim();
    if (text) return { type: 'text', text, depth };
    return null;
  }
  if (node.nodeType !== Node.ELEMENT_NODE) return null;
  if (shouldSkipTag(node)) return null;

  const interactive = isInteractiveElement(node);
  const visible = isVisible(node);
  if (!visible) return null;

  const rect = node.getBoundingClientRect();
  const inViewport = rect.top < window.innerHeight && rect.bottom > 0 &&
                     rect.left < window.innerWidth  && rect.right  > 0;

  const scrollInfo = getScrollInfo(node);

  // Collect relevant attributes
  const INCLUDE_ATTRS = ['type','placeholder','name','role','aria-label','aria-expanded',
    'aria-checked','aria-haspopup','checked','value','alt','title','href','for',
    'data-state','contenteditable'];
  const attrs = {};
  for (const attr of INCLUDE_ATTRS) {
    const val = node.getAttribute(attr);
    if (val !== null && val !== '') attrs[attr] = val.slice(0, 40);
  }

  // Collect text content (only direct text, not from nested interactive elements)
  const text = getDirectText(node).trim().slice(0, 80);

  const children = [];
  for (const child of node.childNodes) {
    const result = walk(child, depth + 1);
    if (result) children.push(result);
  }

  if (interactive) {
    const index = indexCounter++;
    const elem = {
      index, depth, tag: node.tagName.toLowerCase(), attrs, text,
      rect: { x: Math.round(rect.left), y: Math.round(rect.top),
              w: Math.round(rect.width), h: Math.round(rect.height) },
      inViewport, scrollInfo,
      isNew: !seenElements.has(node),
      children,
    };
    seenElements.add(node);  // mark as seen for next extraction
    elements.push(elem);
    return { type: 'interactive', elem, children };
  }

  return { type: 'container', children, depth };
}
```

### 1.6 `flatTreeToString()` — LLM-visible text format

Output format (matching page-agent):
```
[Start of page]
[0]<a href=/home>Home</a>
[1]<input type=text placeholder=Search name=q>
    [2]<button type=submit>Search</button>
*[3]<div role=button aria-expanded=true>Menu (new)</div>
    [4]<a href=/item1>Item 1</a>
    [5]<a href=/item2>Item 2</a>
[6]<div data-scrollable="top=0, bottom=340">Scrollable area</div>
... 1.8 pages below — scroll to see more
[End of visible area]
```

Rules:
- Interactive elements: `[index]<tag attr=val ...>text</tag>`
- New elements: `*[index]<...>`
- Indentation: one `\t` per depth level
- Non-interactive text: printed inline at current indentation, no `[index]`
- Children of interactive elements: indented under parent
- Footer: page scroll position and remaining pages info

### 1.7 `getPageState()` return value

```javascript
{
  url: location.href,
  title: document.title,
  domText: string,          // the flatTreeToString() output
  elements: ElementSnapshot[],  // raw data for coord resolution
  viewportWidth: window.innerWidth,
  viewportHeight: window.innerHeight,
  pageWidth: document.documentElement.scrollWidth,
  pageHeight: document.documentElement.scrollHeight,
  scrollX: window.scrollX,
  scrollY: window.scrollY,
  context: getBrowserContext(),
}
```

`ElementSnapshot`:
```javascript
{
  index: number,
  tag: string,
  attrs: Record<string, string>,
  text: string,
  rect: { x, y, w, h },        // viewport-relative, post-scroll
  inViewport: boolean,
  scrollInfo: { top, bottom, left, right } | null,
  isNew: boolean,
}
```

## Part 2 — New `background/agent.js`

### 2.1 History model

Each step produces a `StepSummary`, NOT a DOM snapshot:

```javascript
// Stored in this._history[]
{
  stepNumber: number,
  evaluation: string,   // "Clicked submit button — success, page navigated to dashboard"
  memory: string,       // "Logged in. Now on dashboard. Need to find friends list."
  nextGoal: string,     // "Click the Friends link in the navigation"
  actionResult: string, // "Clicked [5]<button>Log In</button>"
}
```

### 2.2 Single user message assembly

```javascript
_assembleUserMessage(task, pageState, stepNum) {
  const sections = [];

  // Agent state
  sections.push(
    `<agent_state>\n` +
    `<user_request>\n${task}\n</user_request>\n` +
    `<step_info>\nStep ${stepNum + 1} of ${this._maxIterations}. ` +
    `Time: ${new Date().toLocaleString()}\n</step_info>\n` +
    `</agent_state>`
  );

  // History summaries (never full DOM)
  if (this._history.length > 0) {
    const histLines = this._history.map(h =>
      `<step_${h.stepNumber}>\n` +
      `Evaluation: ${h.evaluation}\n` +
      `Memory: ${h.memory}\n` +
      `Next Goal: ${h.nextGoal}\n` +
      `Action Result: ${h.actionResult}\n` +
      `</step_${h.stepNumber}>`
    ).join('\n');
    sections.push(`<agent_history>\n${histLines}\n</agent_history>`);
  }

  // Current browser state
  const pageHeader =
    `Current Page: ${pageState.title} — ${pageState.url}\n` +
    `Viewport: ${pageState.viewportWidth}×${pageState.viewportHeight}px, ` +
    `page ${pageState.pageWidth}×${pageState.pageHeight}px, ` +
    `scroll (${pageState.scrollX}, ${pageState.scrollY})`;

  sections.push(
    `<browser_state>\n${pageHeader}\n\n${pageState.domText}\n</browser_state>`
  );

  return sections.join('\n\n');
}
```

### 2.3 LLM call — always 2 messages

```javascript
const response = await this._llm.complete({
  system: this.systemPrompt(),
  messages: [
    { role: 'user', content: this._assembleUserMessage(task, pageState, stepNum) }
  ],
  screenshot,  // attached to the user message by each provider; null if useVision=false
});
```

**History is never in the `messages` array.** It is embedded as text inside the user message.

### 2.4 Response schema

The LLM must return a JSON object with this exact shape:

```json
{
  "evaluation_previous_goal": "One sentence: success/failure/uncertain of last action",
  "memory": "1-3 sentences of specific memory and overall progress",
  "next_goal": "One sentence: what to do next and why",
  "action": {
    "ACTION_NAME": { ...params }
  }
}
```

Exactly ONE key in `action`. The value is the action parameters object.

### 2.6 History capping

Keep last 15 step summaries in `this._history`. Each summary is ~200 chars = 50 tokens. 15 summaries = ~750 tokens total. Compare to v1's full DOM per message (8K–30K tokens each).

### 2.7 Step-count warnings

- At 5 steps remaining: inject into history as `<sys>Warning: only 5 steps remaining. Prioritise completion.</sys>`
- At 2 steps remaining: `<sys>CRITICAL: only 2 steps left. Call done() now even if incomplete.</sys>`

## Part 3 — New `background/executor.js`

The executor receives a parsed `action` object and `pageState` (which contains the `selectorMap: Map<index, ElementSnapshot>`). It always goes through `InputControlBridge`. No DOM manipulation, no fallbacks.

### 3.1 `getValidatedCoords(index, pageState)` — core coord resolution

Inspired by `italian_consulate_ext`'s `getElementCoords()`:

```javascript
async getValidatedCoords(index, pageState) {
  const el = pageState.elements[index];
  if (!el) throw new ExecutorError(`Unknown element index ${index}`);

  // 1. If not in viewport, scroll first
  if (!el.inViewport) {
    await this._scrollToElement(el, pageState);
    await this._sleep(500);
    // Re-fetch page state to get updated rect
    const tabId = await this._bridge.getActiveTabId();
    pageState = await this._bridge.getPageState(tabId);
    el = pageState.elements.find(e => e.index === index);
    if (!el) throw new ExecutorError(`Element ${index} disappeared after scroll`);
  }

  // 2. Compute center
  const cx = el.rect.x + el.rect.w / 2;
  const cy = el.rect.y + el.rect.h / 2;

  // 3. Jitter (human-like off-center click, stolen from italian_consulate_ext)
  const { x, y } = this._jitterCoords(el.rect, cx, cy);

  return { x: Math.round(x), y: Math.round(y), el };
}
```

### 3.2 `_scrollToElement(el, pageState)` — bring element into view

```javascript
async _scrollToElement(el, pageState) {
  const vw = pageState.viewportWidth;
  const vh = pageState.viewportHeight;
  // delta: how many pixels to scroll so element center is at viewport center
  const deltaY = Math.round(el.rect.y + el.rect.h / 2 - vh / 2);
  const deltaX = Math.round(el.rect.x + el.rect.w / 2 - vw / 2);
  await this._inputControl.execute('scroll', {
    x: Math.round(vw / 2),
    y: Math.round(vh / 2),
    delta_x: deltaX !== 0 ? deltaX : 0,
    delta_y: deltaY,
    duration_ms: 400,
  }, pageState.context);
}
```

### 3.3 `_jitterCoords(rect, cx, cy)` — off-center human coords

```javascript
_jitterCoords(rect, cx, cy) {
  const padX = Math.max(3, Math.min(rect.w * 0.14, 12));
  const padY = Math.max(3, Math.min(rect.h * 0.18, 10));
  const deadX = Math.max(2, Math.min(8, rect.w * 0.1));
  const deadY = Math.max(2, Math.min(6, rect.h * 0.1));

  const jitterAxis = (min, max, center, dead) => {
    const lo = [min + padX, center - dead];
    const hi = [center + dead, max - padX];
    const useLeft  = lo[1] > lo[0];
    const useRight = hi[1] > hi[0];
    if (useLeft && useRight) return Math.random() < 0.5
      ? randomBetween(lo[0], lo[1]) : randomBetween(hi[0], hi[1]);
    if (useLeft)  return randomBetween(lo[0], lo[1]);
    if (useRight) return randomBetween(hi[0], hi[1]);
    return center;
  };

  return {
    x: jitterAxis(rect.x, rect.x + rect.w, cx, deadX),
    y: jitterAxis(rect.y, rect.y + rect.h, cy, deadY),
  };
}
```

### 3.4 Action implementations

**`_executeClick(index, pageState)`:**
```
1. getValidatedCoords(index, pageState) → {x, y}
2. inputControl.execute('mouse_move', { x, y, duration_ms: 350 + random(0,150) }, context)
3. sleep(80 + random(0, 60))
4. inputControl.execute('mouse_click', { x, y, button: 'left', count: 1 }, context)
5. sleep(100 + random(0, 100))
```

**`_executeType(index, text, pageState)`:**
```
1. _executeClick(index, pageState)
2. sleep(150)
3. inputControl.execute('press_shortcut', { keys: ['control', 'a'] }, context)
4. sleep(80)
5. inputControl.execute('press_key', { key: 'Delete' }, context)
6. sleep(80)
7. inputControl.execute('type', { text, wpm: 55 + random(0,15) }, context)
```

**`_executeScroll(direction, amount, pageState)`:**
```javascript
const AMOUNTS = { small: 200, medium: 500, large: pageState.viewportHeight };
const delta = (direction === 'down' ? 1 : -1) * AMOUNTS[amount];
inputControl.execute('scroll', {
  x: pageState.viewportWidth / 2,
  y: pageState.viewportHeight / 2,
  delta_x: 0, delta_y: delta, duration_ms: 300,
}, pageState.context);
```

**`_executeScrollElement(index, direction, amount, pageState)`:**
```
1. getValidatedCoords(index, pageState) → {x, y}
2. Scroll at those coords (inside the scrollable element)
```

**`_executeSelectOption(index, text, pageState)`:**
```
1. _executeClick(index, pageState)   — open the dropdown
2. sleep(300)
3. Re-fetch page state (new options may have appeared)
4. Find option element by matching text in the new elements list
5. _executeClick(optionIndex, newPageState)
```

**`_executeNavigate(url)`:**
```
1. bridge.navigate(url)
2. bridge.waitForPageSettle()
```

### 3.5 `execute(action, pageState)` dispatcher

```javascript
async execute(action, pageState) {
  const [name, params] = Object.entries(action)[0];
  switch (name) {
    case 'click':          return this._executeClick(params.index, pageState);
    case 'type':           return this._executeType(params.index, params.text, pageState);
    case 'select_option':  return this._executeSelectOption(params.index, params.text, pageState);
    case 'scroll':         return this._executeScroll(params.direction, params.amount, pageState);
    case 'scroll_element': return this._executeScrollElement(params.index, params.direction, params.amount, pageState);
    case 'navigate':       return this._executeNavigate(params.url);
    case 'wait':           return this._sleep(params.seconds * 1000);
    case 'done':           return { done: true, success: params.success, message: params.message };
    default:               throw new ExecutorError(`Unknown action: ${name}`);
  }
}
```

## Part 4 — LLM Provider Changes

All providers already receive `{ system, messages, screenshot }`. The message array is now always length 1 (single user message). No changes needed to provider implementations.

The only change: providers must handle `messages[0].content` that may be a long string (the full assembled user message). This already works.

**Optional enhancement (Phase 2):** Use `tool_choice` / function calling for structured output:
- OpenAI/Codex: `tool_choice: { type: 'function', function: { name: 'AgentOutput' } }`
- Anthropic: `tool_choice: { type: 'tool', name: 'AgentOutput' }`

This is optional because the JSON prompt approach already works for the main use case, and tool calling adds complexity across all providers.

## Part 5 — Context Fresh Fetch Before Native Commands

Inspired by `italian_consulate_ext`'s `getBrowserContext(tabId)` call immediately before each native command (not relying on stale context from earlier):

In `InputControlBridge.execute()`, the `context` parameter is passed by the executor. The executor must pass `pageState.context` (the context snapshot from the latest `get_page_state` call).

For actions where we scroll first and then click, the executor re-fetches `pageState` after scroll (the DOM changes after scroll changes scroll position, so rects and context both update).

## Key Invariants

1. **No DOM actions ever.** `executor.js` only calls `inputControl.execute()`. No `element.click()`, no `dispatchEvent()`, no `element.value = x`. The extractor may call `scrollIntoView` for coord measurement but the actual interaction is always native.

2. **LLM never sees coordinates.** `domText` contains only `[index]<tag>text</tag>`. Rects stay in `elements[]` in memory, invisible to the LLM.

3. **One action per LLM response.** `action` object has exactly one key. The executor expands it into N native commands as needed (scroll → move → click).

4. **Scroll before click.** If `el.inViewport === false`, the executor scrolls first (via python-input-control), waits, re-fetches rects, then clicks. The LLM never needs to know this happened.

5. **Fresh context per command.** After scroll, re-fetch `pageState` before clicking so rects and `context` (window geometry) are current.

6. **History = summaries only.** `this._history` contains `StepSummary[]` — 4 short strings per step, never DOM snapshots. History is embedded as text in the user message, not as additional messages in the `messages[]` array.
